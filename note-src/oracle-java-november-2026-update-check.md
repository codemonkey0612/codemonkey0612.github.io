「Javaの更新を急ぐように」という報道を見ても、自社のシステムに当てはまるのかは判断しにくいものです。

結論から言うと、経営者が自分でJavaを触る必要はほとんどありません。ただし、更新が必要かどうかと、その時期は、発注先や保守担当に早急に確認してください。確認の方法は、メッセージを1通送ることです。

## 何が発表されたのか

[IPAの注意喚起](https://www.ipa.go.jp/security/security-alert/2026/1118-jre.html)によると、2026年11月18日(日本時間)にOracle Javaのセキュリティ更新プログラムが公表されました。

IPAは、脆弱性を突かれた場合の被害として、次の2つを挙げています。

- アプリケーションが異常終了すること
- 攻撃者にパソコンを操作されること

案内されている対策は、Javaを最新版にすることです。影響が大きいため、IPAは早めの更新を促しています。社内PCに入れた業務ソフトも、対象になりえます。

最初に言葉を整理します。

- Java：業務システムの内部で広く使われる言語と、その実行環境
- 脆弱性：プログラムの欠陥のうち、攻撃に悪用されうるもの
- セキュリティ更新プログラム：その欠陥を直す修正版

## 「うちはJavaを使っていない」こそ危うい

Javaは、利用者の画面に名前が出ないことがほとんどです。

たとえば、受発注や在庫のサーバー、帳票の出力、管理ツールの裏側で動いていることがあります。使っている自覚がなくても、動いている可能性はあります。

また、Javaを使っていてもOracle製とは限りません。別の配布元のものを使う例もあります。

IPAのページは、参考情報としてOpenJDKの脆弱性アドバイザリ(2026/11/17付)も挙げています。OpenJDKは、Javaの土台になっている公開ソースです。

配布元によって更新の有無や時期が違うため、「どこのJavaか」を確かめることが大切です。

## 対象になるバージョン

IPAのページに載っている対象は、Oracle Java SEの次のものです。

- 27.0.1.0.3
- 25.0.5.0.3
- 21.0.13.0.3
- 17.0.21.0.3
- 11.0.33.0.3
- 8 Update 511b33

数字が多いので身構えますが、最初に見るのは先頭の「8、11、17、21、25、27」だけです。これがJavaの大きな世代です。

## 私が経営者なら、まずこの4つを聞きます

私は、既存システムの認証や権限の仕組みを調べて直す仕事を、2022年4月から2023年2月まで担当したことがあります。機能ごとに実装がばらばらでした。

私なら、一覧がない場合は優先順位をつけにくいと考え、まず一覧づくりから始めます。だから最初の依頼は、システムの一覧を出してもらうことです。

### 発注先に送る文面(そのままコピーできます)

1．当社のシステムでJavaは使われていますか。使っている場合は、システムの一覧をください。社内PCに入れた業務ソフトも含めてください。

2．使っているのはOracle Javaですか。それとも別の配布元ですか。

3．バージョンは、IPAの注意喚起の対象に当たりますか。「対象」「対象外」「更新済み」のどれかで教えてください。

4．更新するなら、予定日、事前の動作確認の有無、業務が止まる時間、費用の有無を教えてください。

返事が曖昧なら、把握が追いついていないサインかもしれません。私なら、回答の期日を決めてお願いします。

## 慌てて避けたいこと

- 自分でJavaを入れ替えること：業務システムは特定のバージョンを前提にしていることがあり、動かなくなる恐れがあります。
- 出所の分からないサイトから更新ファイルを入手すること：更新は、公式の案内にある方法で行うのが基本です。
- 怖いからと全部止めること：影響範囲が分からないまま止めると、かえって業務への被害が大きくなりかねません。
- 見出しだけで判断すること：IPAなどの一次情報を基準にします。

なお、IPAのページにはライセンスの変更に関する記載もあります。法的な判断は、専門家に確認してください。

## 更新したあとにやること

更新が終わったら、次の4つを確認します。

- 更新後のバージョンを、発注先から文書で受け取る
- 受注入力や帳票出力など、主要な業務を担当者が試す
- 異常終了や遅延が出ていないか、数日間様子を見る
- 更新作業の記録を、保守の履歴として残す

問題が出たら、症状と時刻を保守担当に伝えてください。元に戻す手順があるかも、事前に聞いておくと安心です。
