2026年11月18日(日本時間)に、IPAがOracle Javaのセキュリティ更新について注意喚起を出しました。この記事では、その内容を一次情報どおりに整理します。あわせて、発注先や保守担当に確認したい4つの質問をまとめました。業務システムの開発や保守を外部に任せている中小企業の経営者や担当者に向けた内容です。

先に結論を書きます。自社で何かを操作する必要はほとんどありません。確認すべきなのは、発注先が「どのシステムでJavaを使っているか」を把握しているかどうかです。

## 何が起きたか：IPAの注意喚起の内容

[IPAの「Oracle Java の脆弱性対策について(2026年11月)」](https://www.ipa.go.jp/security/security-alert/2026/1118-jre.html)によると、2026年11月18日(日本時間)にOracle Javaのセキュリティ更新プログラムが公表されました。

ここで用語を一行ずつ整理します。

- Java：業務システムやWebサービスの裏側で広く使われているプログラミング言語と、その実行環境のこと。
- 脆弱性：プログラムの欠陥のうち、攻撃に悪用されうるもののこと。
- セキュリティ更新プログラム：その欠陥を直すための修正版のこと。
- 悪用：攻撃者が欠陥を突いて、意図しない動作をさせること。

IPAは、脆弱性を悪用された場合の被害として、次の2つを挙げています。

- アプリケーションプログラムが異常終了する
- 攻撃者にパソコンを制御される

対策として示されているのは、Oracle社が提供する最新版のソフトウェアへ更新することです。

## 対象バージョンと、CVE-2026-114938の位置づけ

### 対象バージョン

IPAのページに載っている対象は、Oracle Java SEの次のバージョンです。

- 27.0.1.0.3
- 25.0.5.0.3
- 21.0.13.0.3
- 17.0.21.0.3
- 11.0.33.0.3
- 8 Update 511b33(perf版も含む)

数字の羅列に見えますが、見るべきは先頭の「8、11、17、21、25、27」です。これはJavaの大きな世代を表します。自社のシステムがどの世代かは、発注先に聞けばすぐ分かります。

[Oracleの公式アドバイザリ](https://www.oracle.com/security-alerts/cspunov2026.html)では、今回の更新がJava SE向けの11件の新しいセキュリティパッチを含むと説明されています。バージョンの一覧も、IPAの記載と合っています。

### CVE-2026-114938について

CVEは、脆弱性に付けられる共通の識別番号です。同じ番号で呼べば、関係者全員が同じ欠陥の話をしていると確認できます。

IPAのページにも、ネットワーク経由で攻撃を受ける可能性のある脆弱性(CVE-2026-114938)が報告されていると記載されています。攻撃された場合の影響が大きいため、早急にセキュリティ更新プログラムを適用するよう求めています。

[Tenableの解説記事](https://www.tenable.com/blog/java4shell-cve-2026-114938-frequently-asked-questions-about-openjdk-rce-vulnerability)によると、CVE-2026-114938は通称「Java4Shell」です。内容は、JavaがBase64(データを文字列に変換する一般的な形式)を読み解く部分のメモリ破壊の脆弱性です。同記事では、Oracleの評価はCVSS 3.1で8.1とされています。CVSSは、脆弱性の深刻さを0から10で表す共通の指標です。

また同記事には、研究者の検証として、ログインなしでコードを実行できる可能性が示されています。これは第三者の検証結果です。IPAの記載とは分けて読むことをお勧めします。

影響の詳細は、発注先がOracleのリスク一覧を見て判断するのが確実だと考えます。

## 中小企業にとって何を意味するか：Javaは見えないところで動いている

Javaは、画面に「Java」と出ることがほとんどありません。たとえば、次のような場所で動いている可能性があります。

- 受発注や在庫管理などの業務システムのサーバー
- 社内のワークフローや帳票出力の仕組み
- 開発に使う管理ツール

経営者が「うちはJavaを使っていない」と思っていても、実際には裏で動いていることがあります。逆に、Javaを使っていても、Oracle Javaではなく別の配布元のJavaを使っているケースもあります。

IPAのページは参考情報にOpenJDKの脆弱性アドバイザリ(2026/11/17付)も挙げています。OpenJDKは、Javaの元になっている公開ソースです。配布元ごとに更新の有無や時期が違うため、「どの配布元のJavaか」の確認が大切になります。

## 今すぐやること：発注先・保守担当に確認する4つの質問

メールやチャットで、次の4点を送ることをお勧めします。専門知識は要りません。回答が曖昧なら、そこが把握漏れのサインです。

### 質問1：うちのシステムでJavaは使われていますか

使っているシステムの一覧を出してもらいます。サーバーだけでなく、社内PCに入れた業務ソフトも含めて聞きます。

### 質問2：使っているのはOracle Javaですか

Oracle Java、OpenJDK系の別配布など、配布元によって対応の手順が変わります。IPAの注意喚起の対象は、Oracle Java SEです。まずここを切り分けます。

### 質問3：バージョンは対象に当たりますか

先ほどの一覧(8、11、17、21、25、27の各世代)と照らし合わせてもらいます。その結果は「対象」「対象外」「更新済み」の3つで答えてもらうと、読み手が判断しやすくなります。

### 質問4：いつ、どの手順で更新しますか

次の点を確認します。

- 更新の予定日
- 事前の動作確認(テスト)をするか
- 更新中に業務が止まる時間があるか
- 費用が発生するか

IPAは最新版への更新を対策としています。私なら、期日を決めて回答を求めます。

## やらなくてよいこと・慌てて避けたいこと

- 自分でJavaをダウンロードして入れ替えること：業務システムは特定のバージョンを前提に作られていることがあり、勝手に入れ替えると動かなくなる恐れがある。
- 出所の分からないサイトから更新ファイルを入手すること：IPAは、Oracle社が提供する最新版へ更新するよう案内している。
- 「怖いから全部止める」という判断：影響範囲が分からないまま止めると、業務への被害のほうが大きくなりかねない。まず対象かどうかの確認が先である。
- SNSやニュースの見出しだけで判断すること：通称の付いた脆弱性は話題になりやすい。一次情報(IPAやOracleのページ)を基準にする。

なお、IPAのページには、Oracle社が2019年4月16日以降のJavaのリリースについて、ライセンスの変更を案内しているとの記載もあります。更新の際は、ライセンス条件が自社の使い方に合っているかも、発注先と確認すると安心です。ライセンスの法的な判断は、専門家に確認してください。

## 更新後の確認と、困ったときの相談先

更新が終わったら、次の点を確認します。

- 更新後のバージョンを、発注先から文書で受け取る
- 主要な業務(受注入力、帳票出力など)が普通に動くかを、担当者が試す
- 異常終了や遅延が出ていないか、数日間様子を見る
- 更新作業の記録を、保守の履歴として残す

問題が出たときは、まず保守担当に症状と時刻を伝えます。元に戻す手順(切り戻し)があるかも、事前に確認しておくと安心です。

## まとめ

- IPAは2026年11月18日(日本時間)に、Oracle Javaの更新を適用するよう呼びかけた。
- 対象は、Oracle Java SEの8、11、17、21、25、27の各更新版である。
- 発注先には、使用有無、配布元、バージョン、更新計画の4点を聞く。
- 自己判断で入れ替えず、一次情報を基準に進める。
